# Selector strategy

**Invariant, not a preference.** A selector's only job is to still find the same element tomorrow.
Everything below follows from that one requirement.

This document deliberately names no attribute as *the* right one. `data-testid`, `data-qa`,
`data-aid`, `data-test`, `data-cy` are all conventions some teams use and others have never heard
of, and plenty of applications have none of them. Which one this app uses — if any — is
**measured** at survey and recorded in `Meta.Selector-strategy`, not assumed here.

---

## S1. The only test that matters: does the value survive a reload?

A selector built on a value the framework generates at runtime looks perfect in one snapshot and
fails on the next deploy, or the next page load. This is the failure that gets past every other
check — the artifact grounds cleanly, the code compiles, the test passes once.

So: **load the page twice and compare.** Anything whose value changed is generated, and is
unusable no matter how convenient it looks. One reload, and it settles the question for the whole
page at once.

Known-generated shapes, as a shortcut when you cannot reload — but the reload is the authority:

| Looks like | Comes from | Verdict |
|---|---|---|
| `:r3:`, `:rb:` | React `useId` | never usable |
| `react-aria4907020324-_r_be_` | React Aria | never usable |
| `mui-3821`, `radix-:r7:`, `headlessui-menu-item-4` | MUI / Radix / Headless UI | never usable |
| `css-1q2w3e`, `sc-bdVaJa` | Emotion / styled-components | never usable |
| `_filterPanel_a1b2c` used **whole** | CSS modules, hashed at build | not usable as-is — see S2 |
| `xrhk`, `a7f3b2` as a class | atomic / minified CSS | never usable |

## S2. A hashed class still has an authored stem inside it

CSS-module classes are the common case where the value is *half* stable. `_filterPanel_a1b2c` is
`_filterPanel_` — written by a developer, changes only when they rename it — plus a build hash that
changes whenever the file does.

So the stem is usable and the whole string is not:

```
[class*='_filterPanel_']     stable — matches the authored part
.\_filterPanel_a1b2c         breaks on the next build
```

Take the stem, keep the leading and trailing underscore so it cannot collide with a substring of
another name, and never include the hash. If a class has no separable stem — `xrhk`, `css-1q2w3e`,
a single minified token — there is nothing to keep and this route is closed.

## S3. Order of preference, given what the app actually offers

Work down this list. Stop at the first tier the app supports well, and record which one in
`Meta.Selector-strategy`.

1. **A purpose-built test attribute**, whichever this app uses. Best when present, because it exists
   precisely so tests can depend on it.
2. **Semantics the app cannot change without changing behaviour** — `role`, `type`, `name`, `href`,
   `aria-label` on a control whose accessible name is functional rather than decorative.
3. **An authored class stem** (S2), or a `data-*` attribute that carries meaning rather than state.
4. **Structure and text**, including XPath (S4).

Two cautions on tier 2. Visible text and labels move with copy edits and translations, so a
text-anchored selector on a localised app is a maintenance cost the team may not want — check
`conventions.md` for whether they already accept it. And `aria-label` on an icon-only button is
often the only thing available, which makes it both the best and a fragile option; say so in
`Notes:` rather than picking silently.

## S4. XPath is legitimate, not a last resort to be ashamed of

Plenty of applications are not component frameworks. Server-rendered pages, older stacks, anything
generated by a form builder or a CMS — these routinely have no test attributes, no meaningful
classes, and nothing but structure to go on. **XPath is the correct tool there**, and refusing it
produces worse selectors, not better ones, because the alternative is a chain of `nth-child`.

Where it earns its keep:

- anchoring on a **stable text node and walking to a control** — a label's `for`, a heading's
  following table, a cell in the column headed by a known word
- axes CSS cannot express: `ancestor::`, `following-sibling::` past a variable gap, `parent::`
- matching on text content when nothing else distinguishes two identical controls

Same rules apply: anchor on the parts that a developer wrote, not on positions the framework
decided. `//table[@summary='Orders']//tr[td[text()='Shipped']]` is stable; `//div[3]/div[2]/span`
is a coin flip. And an XPath still resolves inside its `Scope:` like any other selector — grounding
counts matches within the scope root, not the document.

## S5. Position is scoped or it is nothing

`nth-child` and index-based paths are legitimate **inside a component root**, where the position is
part of the component's own structure — the third cell of a row whose columns are fixed, the first
option of a listbox. They are not legitimate from the page down, where any layout change
reorders them.

The difference is `Scope:` (`rules/element.md` E7). A position that is meaningful relative to a
grounded root is a description of that component; a position relative to `document` is a guess
about the whole page.

## S6. The project's existing convention outranks the theoretically better hook

If the app exposes a clean test attribute but the existing Page Objects locate by class stem,
**follow the existing Page Objects**. A codebase with one consistent strategy is easier to maintain
than one with a better strategy applied to a third of it.

Report the mismatch — it is usually worth fixing at the source, and the team may not know the
attribute is there — but report it, do not act on it unilaterally. `conventions.md` is the
authority; this document only says how to judge candidates when it is silent.

## S7. Every selector is grounded, whatever tier it came from

None of the above is a substitute for checking. A selector from the best tier available is still a
claim until the page confirms it resolves, exactly once, inside its scope (`rules/element.md` E8,
rules V043–V045). A well-chosen selector that matches nothing is worth no more than a badly chosen
one.
